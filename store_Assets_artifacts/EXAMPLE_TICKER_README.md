# EXAMPLE_TICKER — what every asset folder holds

Each `<TICKER>/` folder in this store carries the same nine files, named after
the manifest enacted in
[`module_skills/act_naming_conventions.md`](../module_skills/act_naming_conventions.md):
every file is prefixed with its ticker, every time series carries its grid in
timeframe slots (`ss-mm-hh-dd-MM` — the active granularity as a zero-padded
number, so a listing sorts finest to coarsest), and a file copied out of its
folder still says which asset it belongs to and which grid it lives on.

**There is no OHLCV here.** The canonical primary-failover price series and
its 15m/1h/4h aggregations live only in `store_db/research_ohlcv.duckdb` —
that is the market object every stage reads. The strategy logic is one shared
file for the whole project, `module_ml/strategy.py`: code is common, the
parameters below are per asset.

## The nine files (in `LC_COLLATE=C` listing order)

### `<TICKER>_README.md`

The per-asset guide, generated by `make ml-status`: the file table with
sizes, label statistics, fold-by-fold classification and PnL tables, and the
commands that reproduce the folder.

### `<TICKER>_features_ss-15-hh-dd-MM.parquet` · `…_ss-mm-01-dd-MM…` · `…_ss-mm-04-dd-MM…`

X, one parquet per timeframe (15m, 1h, 4h). Columns: `decision_ts` (bar-open
UTC epoch ms of the 15m decision grid) plus the five feature families computed
on that timeframe's own closed bars and gathered causally to the decision:

| column | what it computes |
|---|---|
| `ema20_minus_ema50_over_atr14` | trend: fast-minus-slow EMA spread, ATR-normalised |
| `centered_rsi14` | momentum: Wilder RSI(14) mapped to [−1, 1] |
| `atr14_over_close` | volatility: ATR(14) relative to price |
| `range_position_20` | structure: close inside the 20-bar high–low range |
| `log_volume_zscore_50` | activity: z-score of log volume over 50 bars |

The filename carries the timeframe, so the columns carry only their family
names. 194,848 rows per file under the current research window — every value
from the last **closed** bar of its timeframe, no NaN after the warm-up.

### `<TICKER>_label_events_ss-15-hh-dd-MM.parquet` — regenerable work product

Y, written by `module_ml/labels.py`: one triple-barrier event per decision.
Columns: `decision_ts`, `entry_ts` (decision + 1 minute), `y` (−1/0/+1),
`event_end_ts` (exclusive), `entry_observable` (the entry minute printed a
trade), `label_valid` (the event resolved unambiguously), `event_resolution`
(which barrier ended it), `entry_price`, `upper_barrier`, `lower_barrier`,
`exit_reference_price`.

### `<TICKER>_model_evaluation.json`

Classification results, written by `module_ml/train.py`: `validation.fold_2..4` and
`final_holdout` — each `{prior_logloss, model_logloss,
relative_logloss_skill, scored_row_count}` — plus `gain_importance` (total
gain per feature column), `class_counts` (short/neutral/long over the
supervised population), `labels` (`decision_count`, `ambiguous_event_count`,
`unobservable_entry_count`, `trainable_row_count`) and `segments`
(training/purged/window/scored row counts per fold).

### `<TICKER>_oos_predictions_ss-15-hh-dd-MM.parquet` — regenerable work product

Out-of-sample class probabilities from `module_ml/train.py`: `decision_ts`,
`oos_fold_id`, `p_short`, `p_neutral`, `p_long` — the **full** prediction
windows of F2–F5, the only inputs the strategy layer may use to choose its
threshold.

### `<TICKER>_parameters.json`

The one parameters file — everything the strategy runs with, written by
`module_ml/hpo.py` when the search runs. Two sections:

- `experiment_configuration` — the a-priori settings: `ticker`,
  `research_window`, `folds` (bounds, validation/final-holdout ids, warm-up,
  purge and embargo rules), `features` (timeframes, families, columns,
  indicator periods), `labels` (barrier multiplier, horizon, sigma, touch
  rule, resolution codes), `hyperparameter_search` (sampler, seed, trial
  count, objective, space, fixed XGBoost parameters), `strategy` (cost rate,
  threshold grid, minimum trades, trend gate).
- `hyperparameter_search_result` — what the search chose: `best_params` (the
  eight searched XGBoost hyper-parameters), `best_logloss`, `trial_count`.

### `<TICKER>_strategy_evaluation.json`

The strategy's choices and outcomes, written by `module_ml/strategy.py`:
`entry_edge_threshold` (τ) with `entry_edge_threshold_constraint_met`,
`selection_score_mean_sharpe`, `execution_cost_rate_per_trade_side`, then per
fold (`validation.fold_2..4`, `final_holdout`): `sharpe`, `max_drawdown`,
`trade_count`, `hit_rate` (null when no trades), `average_trade_return`,
`exposure`, `exit_counts` (upper/lower/vertical/ambiguous) and
`final_equity`; the final holdout also carries the weekly-sampled
`equity_curve` (values only — its last point is `final_equity`).

## Tracked vs regenerable

`<TICKER>_parameters.json` and `<TICKER>_README.md` are committed — they make
a folder readable without a run. Everything else is regenerable from the
DuckDB database by the ML chain of `make ml-all` (the Makefile is the one
authority for stage order; HPO is the expensive step, the rest takes seconds).
